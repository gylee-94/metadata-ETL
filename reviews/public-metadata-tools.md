# 공개 메타데이터 도구 리뷰

검토일: 2026-10-13. 아래는 공개 README 기반의 기능 검토입니다. 세 도구의 성능 순위를 매기지 않습니다. 서로 다른 입력·출력과 평가 단위를 먼저 이해하는 것이 목적입니다.

## MetaMuse

GEO 샘플 메타데이터 추출·큐레이션·정규화를 다룹니다. README는 GEO/PubMed SQLite 입력, 샘플별 처리, 품질 검토 반복, CSV·Parquet 출력을 설명합니다. [공개 README](https://github.com/Ekansh-Mittal1/MetaMuse/blob/d7f6c1a5b820a79b11bcf19c07cfd4ad8fa6685c/README.md)

학습 질문: 원본 필드와 모델 추출값은 어떻게 구분하는가? 품질 검토 전후 어떤 오류가 줄거나 늘어나는가? 반복 실행에서 같은 입력을 어떻게 식별하는가? 질문에 대한 답은 코드 추적과 실행 결과를 추가해 기록한다.

## LLMDap와 Pre-Meta

LLMDap은 LLM·RAG를 활용한 메타데이터 생성 프레임워크입니다. 문서 문맥 축소, 출력 스키마, 필드별 평가 모듈을 나누며 README에서 Pre-Meta 논문을 연결합니다. 필드 형식에 맞는 출력과 사실상 정확한 출력은 별개로 검증해야 합니다. [공개 README](https://github.com/SINTEF-SE/LLMDap/blob/94c008d120f34e727eddea6f6e57a01968a4f9ad/README.md), [Pre-Meta 논문](https://doi.org/10.1093/bioinformatics/btaf519)

학습 질문: 문맥 축소 전후 필요한 근거가 보존되는가? 필드별 평가 지표는 실제 사용 목적을 반영하는가? 입력 문서와 스키마가 바뀌면 캐시·평가 조건도 달라지는가?

## MetaHQ

여러 자원에서 큐레이션한 공개 오믹스 메타데이터를 통합·배포하는 플랫폼입니다. CLI 설치와 DB 설정을 분리합니다. 소프트웨어는 BSD-3-Clause, 주석 DB는 CC BY-NC 4.0으로 안내하므로 코드와 데이터의 조건을 구분합니다. [공개 README](https://github.com/krishnanlab/meta-hq/blob/cd1ff50e37e2eeb287e237b40963874e68839dd3/README.md)

학습 질문: 검색 결과에 없는 연구가 배포본에도 없는가? 질환 검색 결과가 전체 샘플 목록을 뜻하는가? 배포 버전이 바뀌면 동일 질의의 결과가 어떻게 달라지는가? [검증 절차](../experiments/metahq-coverage/README.md)에서 별도로 다룬다.

## 비교할 때 고정할 조건

| 비교 축 | 기록할 내용 |
|---|---|
| 입력 | 메타데이터, 문서, 기존 주석 중 실제 제공된 자료 |
| 출력 단위 | 연구, 샘플, 필드, 관계 중 무엇을 반환하는지 |
| 근거 | 값과 원문 위치를 함께 확인할 수 있는지 |
| 실행 | 코드 commit, 데이터 버전, 설정, 실패와 재시도 |
| 평가 | 정확도, 수록 범위, 검색 회수율을 구분 |

README에 설명이 없다는 이유만으로 기능이 없다고 결론 내리지 않는다. 실제 실행 전에는 정확도·속도·비용 수치를 기재하지 않는다. 기존 기능의 실행 성공만으로 특정 분석 목적의 충족을 주장하지 않는다.
